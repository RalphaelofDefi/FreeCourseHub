# 9. FREEMIUM AND MONETIZATION SYSTEM
# ============================================================

MONETIZATION="
Implement an administrator-controlled freemium and
pay-per-course access system.

ADMIN CONFIGURATION:

The administrator must control:

- Number of free course unlocks for new users.
- Price per additional course.
- Payment currency.
- Enable or disable free allowances.
- Enable or disable paid unlocking.

DEFAULT PAYMENT MODEL:

PAY PER COURSE.

Example:

Free unlock allowance = 5
Price per additional course = NGN 200

A newly registered user receives five free unlocks.

FREE UNLOCK WORKFLOW:

1. User logs in.
2. User opens a published course.
3. User clicks Unlock Course.
4. Backend checks whether the user already unlocked it.
5. If already unlocked, grant access without charging.
6. Otherwise, check remaining free allowance.
7. If free allowance remains, create a free unlock.
8. Deduct one free unlock.
9. Record the unlock in MySQL.

PAID UNLOCK WORKFLOW:

When free allowance is exhausted:

1. Display the configured price.
2. User initiates Paystack payment.
3. Backend initializes a transaction.
4. User completes checkout.
5. Backend verifies the transaction.
6. Create the course unlock only after successful verification.
7. Record the transaction and unlock.
8. Allow permanent repeat access to that course while it remains
   available.

IMPORTANT RULES:

- Never charge twice for the same course.
- Never deduct free allowance twice.
- Never unlock based on frontend messages alone.
- Use database transactions.
- Use unique constraints for unlock records.
- Handle simultaneous unlock requests safely.
- Maintain a complete unlock audit trail.

CHANGING ADMIN SETTINGS:

Changing the free allowance should affect new registrations
by default.

Do not automatically reset existing users' balances.

Existing users retain their remaining allowance unless the
administrator explicitly adjusts it.
"

# 10. PAYSTACK INTEGRATION
# ============================================================

PAYSTACK="
Integrate the official Paystack API.

Implement:

- Server-side transaction initialization.
- Paystack checkout redirect.
- Server-side transaction verification.
- Paystack webhook handling.
- Transaction reference validation.
- Amount validation.
- Currency validation.
- Duplicate transaction protection.
- Failed payment handling.
- Cancelled payment handling.
- Payment history.

PAYMENT WORKFLOW:

1. User clicks Unlock Course.
2. Backend checks course access eligibility.
3. Backend retrieves the current course price.
4. Backend creates a pending payment record.
5. Backend initializes Paystack checkout.
6. User completes payment.
7. Paystack redirects the user.
8. Backend verifies the transaction independently.
9. Backend validates reference, amount, currency and status.
10. Backend creates one course unlock.
11. User receives access.

Use idempotent payment processing.

Never expose the Paystack secret key in frontend code.

ENVIRONMENT VARIABLES:

PAYSTACK_PUBLIC_KEY=
PAYSTACK_SECRET_KEY=
PAYSTACK_CALLBACK_URL=

Use Paystack test keys during localhost development.

The system must not unlock a course just because the user
visits the payment callback URL.

Verify payment through the official API and validate webhook
signatures before processing webhook events.
"
